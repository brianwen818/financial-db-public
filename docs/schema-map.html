financial-db Schema 圖

兩條管線各一張圖，raw → processed → view 三層並列。每張卡片是一張實體表（或 view）， 列出全部欄位與型別；連線是血緣——哪個 raw 進到哪個 processed、哪個 view 讀哪份 Parquet、 哪個 view 疊在哪個 view 上。滑鼠移到卡片上會亮起它的上下游。 全部欄位型別直接 dump 自兩個 DuckDB 與 Parquet 檔（2026-09-29），不是抄文件。

raw → processed（實體轉換） processed → view（read_parquet） view → view（SQL 疊加） 更新時相依／外部輸入 PK 自然鍵（去重／唯一性斷言的鍵） part Hive 分區鍵

finmind.duckdb 19 views + 3 macros・零 table

raw 層日期都是字串、欄名照上游；processed 層才定型。價格 raw 有 ticker（一檔一檔案）與 market（一天一檔案）兩種形狀，schema 相同，processed 去重時 market 優先。

  • AB高低價差%→ high_low_spread_pct
