兩條台股資料管線，一套分層契約

個人財經資料庫 financial-db 的完整架構：raw 層原樣保存、processed 層定型去重分區、 DuckDB 只放 view 零 table、Windows 工作排程每日更新。本頁整理自程式碼與資料庫實測 （2026-09-29），數字以實測為準，repo README 的快照值（09-03）已部分過時。

FinMind 管線 API → Parquet → View

① 取得：抓什麼、怎麼抓

資料集註冊在 config/datasets.yml（history_start: 1994-10-01）。 客戶端 utils/finmind_client.py 用原生 requests（不用官方 SDK，避免它自己 throttle 打架）， 搭配跨行程 token-bucket 限流器（state/rate_limit.json，預算 = 時數上限 × 0.9）。 402 退避重試 8 次、429/5xx 指數退避 5 次。

沒有抓的：財報、三大法人、融資券、股利明細、分價量表、盤中/分鐘資料。 raw 層一律 Parquet（zstd-3），欄名照上游（max、min、Trading_Volume…），日期留字串，寫入走 .tmp + os.replace 原子換檔。

② 處理：raw → processed

價格（processing/prices.py）四步驟：

  • 改名 + 定型 — max→high、min→low、Trading_Volume→volume、Trading_money→turnover_value、Trading_turnover→transactions；日期轉 DATE、金額轉 BIGINT；stock_id 刻意留 VARCHAR（0050、00679B、TAIEX 轉數字就壞了）。
  • 過濾範圍 — 全市場單日回約 43,700 個代碼，依代碼形狀只留 common + etf，丟掉權證與 TDR（約 4 萬個代碼/日）。
  • 重新分區 — 從「一檔一個檔案」翻轉成「一天一個檔案」：year=YYYY/month=MM/YYYY-MM-DD.parquet。這是查詢效能的基礎。
  • 去重 — 同一 (stock_id, date) 可能同時來自 ticker 檔與全市場檔，ROW_NUMBER() 留一筆、全市場優先（收盤後權威快照）。全量重建走 staging 目錄 + 原子 swap。

維度各有自然鍵，不是 SELECT DISTINCT *：tw_stock_info 以全部內容欄位去重（min()=首見日）、tw_industry 以 (stock_id, industry, sub_industry)（max()=最後看到）。 三個是算出來的：交易日曆 1994–1998 段由觀測價格日期反推（含週六盤）；已下市清單 = 掃描 ∪ 下市公告 − 現有主檔；確認休市日（目前 1 天）。

③ 產出：19 個 view + 3 個 macro

由 build_db.py 依檔名順序執行 sql/**/*.sql（{{DB_ROOT}} 代換資料根目錄），全部 CREATE OR REPLACE。

價格v_daily_prices・v_adj_daily_prices・v_prices_combined・v_daily_prices_enriched未還原／還原／並列（含 adj_factor）／join 主檔與產業。都帶 year/month 分區鍵。

Macro：daily_prices_between(lo,hi)、adj_daily_prices_between(lo,hi)、prices_combined_between(lo,hi)——自動加 year BETWEEN 述詞做分區裁剪，約快 4 倍。

④ 更新：每日增量 + 每週對帳

  • 每日（daily_update.py，一〜六 18:30，9–22 次呼叫、秒級）：先 ingest 三個維度快照，再對兩個價格集抓「新日期 ∪ 最近 3 天重抓（FinMind 結算後會改成交量）∪ 範圍內缺漏」的聯集，逐日 market 呼叫 + 逐日重寫 processed；超過 30 天斷路，叫你去跑 backfill。最後重建維度與 view。
  • 每週（weekly_refresh.py，週日 02:00，約 3,217 次呼叫、43–47 分）：還原價全量重抓約 3,150 檔（每次除權息都改寫整條歷史，不能 append），staged 重建；再跑對帳 A/B/C/D（缺日、稀薄日、零列 ticker、停更 ticker）修未還原價。
  • 年度稽核（discover_delisted.py，不排程）：272 次呼叫重掃已下市 universe。

TEJ 管線 Excel COM → xlsx → Parquet → View

① 取得：沒有 API，是驅動 Excel

來源是 TEJ Smart Wizard 增益集（C:/TejPro/.../excel03menu.xla）。 每本 xlsx 的 A1 儲存格註解存著 TEJ 查詢字串：價格查 waprcd1（調整後日行情，33 個欄位）、 指數查 widxs（指數成分，7 個欄位）。查詢定義不含證券代碼——代碼在每列 A 欄， 所以改寫 A 欄再 refresh 就能得到新證券的完整歷史，create_workbooks.py 就是這樣從樣板長出 2,000+ 本新 workbook 的。

② 處理：xlsx → Parquet

  • 解析（processing/xlsx_reader.py）— 不開 Excel 也不用 openpyxl：把 xlsx 當 zip，用 iterparse 串流讀 sheet1.xml，靠儲存格 r 參照定位（空格不出現在 XML）。表頭必須逐字符合契約否則 WorkbookFormatError。
  • 定型（schema.py／index_schema.py）— Excel 序號日期（epoch 1899-12-30）轉 DATE；"2330 台積電" 從第一個空格切成 stock_id/stock_name；中文欄名轉英文（收盤價→close、次日參考價→next_ref_price…）；加 market、source_file、ingested_at。價格 35→37 欄，view 加分區鍵成 40 欄。
  • 不去重，改斷言唯一 — (stock_id, date)／(index_id, date, stock_id) 必須唯一、同指數兩個年度檔不得重疊日期，違反就 fail。
  • 永遠全量重建、不 append — 排序後依 year=/month=/YYYY-MM.parquet（月分區）寫出，整個資料集蓋在 __staging 再原子 swap。單本解析失敗會跳過續跑；解析出 0 列則拒絕換入空資料集。
  • 對帳層 — workbook_scan.py 只讀 zip 中繼資料產出 workbook inventory Parquet，供 v_workbook_status 在重建後再次比對列數（rows_delta）、落後天數與查詢契約。

排程註冊的兩個坑

① 一律用 PowerShell Register-ScheduledTask，不要用 schtasks /TR——路徑空格會被切開（FinMind 曾因此靜默失敗一週）。 ② TEJ 必須設「只在使用者登入時執行」：Excel 無法在 Session 0 啟動。FinMind 沒有此限制。 ③ 跨年第一個交易日 TEJ 會大聲失敗——2027.xlsx 指數年度檔要手動在增益集建一次（見 tej-wizard/docs/operations.md）。 ④ 漏跑不用手動補：下次執行會插入所有缺漏交易日。

查詢方式與陷阱

import duckdb
con = duckdb.connect(r"<repo>\db\finmind\finmind.duckdb",
                     read_only=True)          # 一律 read_only，寫入連線會鎖住排程更新

con.execute("""
    SELECT date, stock_id, close, volume
    FROM daily_prices_between('2024-01-01', '2024-03-31')   -- 用 macro 才會裁剪分區
    WHERE stock_id = '2330'
    ORDER BY date
""").df()
  • stock_id 是字串：'0050' 不是 50。
  • 日期範圍用 macro：Parquet 依 year/month 分區，單寫 WHERE date BETWEEN 不會裁剪分區（finmind 實測一季 0.56s → 0.13s；tej 48ms → 28ms）。
  • FinMind 還原價 survivors-only：用 v_adj_daily_prices 的結論必須標註；無偏誤橫斷面用 v_daily_prices + v_securities_all（起點 2004-02-11），或改用 TEJ。
  • TEJ 只有 OHLC 是還原價：同列 bid/offer/next_ref_price/next_limit_* 是未還原原始報價（2330 在 2000-09-04：close 27.99 vs next_ref_price 133.5，差 4.8 倍），混用必錯。
  • 單位是 TEJ 的：成交量千股、成交值千元、市值百萬元；FinMind 的 volume 是股（不是張）。
  • 回測歷史指數用 index_members_on('TWN50', 日期) 取當日成分。
  • 最新一天可能不完整：用 v_last_trading_day 取日期，先用 v_daily_coverage 確認該日列數沒有異常偏低。
